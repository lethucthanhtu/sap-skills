## 1. Exception Class Hierarchy

```
cx_root  (abstract — superclass của tất cả exception classes)
  │
  ├── cx_static_check
  │     ├── Caller BẮT BUỘC handle hoặc declare RAISING
  │     ├── Syntax check cảnh báo nếu thiếu RAISING declaration
  │     ├── Dùng cho: recoverable business errors
  │     └── Ví dụ custom: ZCX_VALIDATION_ERROR, ZCX_BUSINESS_ERROR, ZCX_NOT_FOUND
  │
  ├── cx_dynamic_check
  │     ├── Caller KHÔNG bắt buộc declare — nhưng NÊN handle
  │     ├── ⚠️ Quirk: Nếu không handle VÀ không declare RAISING ở mọi level
  │     │         → tự động chuyển thành CX_NO_HANDLER tại runtime → ST22 dump
  │     ├── SAP khuyến nghị: dùng CX_STATIC_CHECK thay vì CX_DYNAMIC_CHECK
  │     ├── cx_sy_* runtime exceptions đều kế thừa từ đây
  │     └── Ví dụ custom: ZCX_INVALID_PARAMETER (nếu cần)
  │
  └── cx_no_check
        ├── KHÔNG được declare trong RAISING — syntax error nếu khai báo
        ├── Propagate tự động qua tất cả call stack
        ├── Dùng cho: fatal, system-level errors không thể recover
        ├── cx_sy_* system exceptions (cx_sy_zerodivide, cx_sy_itab_line_not_found...)
        └── KHÔNG tạo custom subclass của cx_no_check trừ trường hợp đặc biệt

Key methods kế thừa từ cx_root (có thể gọi trên mọi exception object):
  get_text( )       → RETURNING VALUE(result) TYPE string  — exception message text
  get_longtext( )   → long text (nếu có)
  get_source_position( ) → program, include, line number nơi raise
  previous          → TYPE REF TO cx_root — chained previous exception (nếu có)
  is_resumable      → TYPE abap_bool — abap_true nếu là resumable exception
```

> **Lời khuyên thực tế từ Clean ABAP:**
> Chỉ dùng `cx_static_check` và `cx_no_check`. Tránh `cx_dynamic_check` vì behavior
> "chuyển thành cx_no_handler" gây khó debug và không mang lại lợi ích rõ ràng.

## 2. Khi Nào Dùng Loại Nào

```
cx_static_check  — dùng khi:
  ✅ Caller CÓ THỂ recover một cách có ý nghĩa (business logic error)
  ✅ Caller NÊN biết về exception để xử lý đúng
  ✅ Exception là phần expected của flow (validation fail, not found, ...)
  Examples: ZCX_VALIDATION_ERROR, ZCX_NOT_FOUND, ZCX_BOOKING_CONFLICT

cx_no_check  — dùng khi:
  ✅ Caller KHÔNG THỂ recover — program state không còn tin cậy
  ✅ Là programming error (null pointer, array out of bounds)
  ✅ Là system/infrastructure error (out of memory, DB unavailable)
  ✅ Exception sẽ propagate nhiều tầng mà không có handler hợp lý
  Examples: cx_sy_zerodivide, cx_sy_itab_line_not_found (system)
            ZCX_CONFIGURATION_ERROR (missing mandatory config)

cx_dynamic_check  — tránh dùng vì:
  ⚠️ Không bắt buộc declare → dễ bị bỏ qua → silent ST22 dump
  ⚠️ Quirk CX_NO_HANDLER gây confusion
  ⚠️ Không có lợi ích rõ ràng so với cx_static_check hoặc cx_no_check
  Nếu thực sự cần: chỉ dùng cho "programming errors caller nên prevent"
  (ví dụ: division by zero trong public method khi có thể validate trước)
```

## 3. Tạo Custom Exception Class

### Bước tạo trong ADT (recommended) hoặc SE24

```
ADT: New → ABAP Class → Class Kind: Exception Class
     Superclass: ZCX_BASE_ERROR (custom base) → CX_STATIC_CHECK
SE24: Class Type = Exception Class, Superclass = CX_STATIC_CHECK
```

### Structure của custom exception class

```abap
"! <p class="shorttext synchronized" lang="en">Validation error for travel data</p>
CLASS zcx_travel_validation DEFINITION
  PUBLIC
  INHERITING FROM cx_static_check
  CREATE PUBLIC.

  PUBLIC SECTION.
    INTERFACES if_t100_message.  " ← implements SAP T100 message interface

    " Constants cho mỗi error text (generated by SE24/ADT khi define exception texts)
    CONSTANTS:
      BEGIN OF begin_date_required,
        msgid TYPE symsgid VALUE 'ZTR',  " message class
        msgno TYPE symsgno VALUE '001',  " message number
        attr1 TYPE scx_attrname VALUE '',
        attr2 TYPE scx_attrname VALUE '',
        attr3 TYPE scx_attrname VALUE '',
        attr4 TYPE scx_attrname VALUE '',
      END OF begin_date_required,

      BEGIN OF end_date_before_begin,
        msgid TYPE symsgid VALUE 'ZTR',
        msgno TYPE symsgno VALUE '002',
        attr1 TYPE scx_attrname VALUE 'TRAVEL_ID',  " maps to attribute below
        attr2 TYPE scx_attrname VALUE '',
        attr3 TYPE scx_attrname VALUE '',
        attr4 TYPE scx_attrname VALUE '',
      END OF end_date_before_begin.

    " Custom attributes cho message placeholders
    DATA travel_id TYPE /dmo/travel_id.

    METHODS constructor
      IMPORTING
        !textid   LIKE if_t100_message=>t100key OPTIONAL
        !previous LIKE previous                 OPTIONAL
        !travel_id TYPE /dmo/travel_id          OPTIONAL.

  PROTECTED SECTION.
  PRIVATE SECTION.
ENDCLASS.

CLASS zcx_travel_validation IMPLEMENTATION.

  METHOD constructor.
    " Chain: call superclass constructor
    CALL METHOD super->constructor
      EXPORTING
        previous = previous.

    me->travel_id = travel_id.

    " Set T100 key: default to class-level constant nếu không pass textid
    CLEAR me->textid.
    IF textid IS INITIAL.
      if_t100_message~t100key = begin_date_required.  " default text
    ELSE.
      if_t100_message~t100key = textid.
    ENDIF.
  ENDMETHOD.

ENDCLASS.
```

### Hierarchy cho production — abstract base exception

```abap
" ✅ Pattern: tạo abstract base class per domain, inherit từ đó
" → cho phép CATCH toàn bộ domain errors với 1 CATCH statement

" Base class — abstract
CLASS zcx_travel_error DEFINITION PUBLIC ABSTRACT
  INHERITING FROM cx_static_check.
ENDCLASS.

" Specific exceptions inherit từ domain base
CLASS zcx_travel_validation DEFINITION PUBLIC
  INHERITING FROM zcx_travel_error.   " ← inherit từ domain base, không phải cx_static_check trực tiếp
  ...

CLASS zcx_travel_not_found DEFINITION PUBLIC
  INHERITING FROM zcx_travel_error.
  ...

CLASS zcx_travel_conflict DEFINITION PUBLIC
  INHERITING FROM zcx_travel_error.
  ...

" Caller có thể catch cụ thể hoặc catch tất cả travel errors
TRY.
    travel_service->create_booking( booking ).
  CATCH zcx_travel_validation INTO DATA(lx_val).   " specific
    handle_validation( lx_val ).
  CATCH zcx_travel_error INTO DATA(lx_travel).     " catch all domain errors
    handle_travel_error( lx_travel ).
ENDTRY.
```

## 4. Exception Texts — if_t100_message

SAP dùng bảng **T100** để lưu translatable message texts (transaction SE91).
Interface `if_t100_message` cho phép exception class tích hợp với T100.

### Hai interfaces liên quan

```
if_t100_message   — static message texts (defined khi tạo exception class trong SE24)
                    Attributes: T100KEY (msgid + msgno + attr1..4)
                    get_text( ) → resolves T100 message → returns string

if_t100_dyn_msg   — dynamic message texts (set T100 info at runtime, không cần predefined constant)
                    Thường dùng khi wrap FM/BAPI errors vào exception
```

### Raise với predefined text constant

```abap
" ✅ Dùng constant đã define trong exception class (recommended)
RAISE EXCEPTION TYPE zcx_travel_validation
  EXPORTING
    textid    = zcx_travel_validation=>end_date_before_begin
    travel_id = ls_travel-travel_id.
" → get_text( ) sẽ return: "End date must be after begin date for travel &1"
"   với &1 = travel_id value

" ✅ Dùng default text (không pass textid)
RAISE EXCEPTION TYPE zcx_travel_validation.
" → constructor dùng default constant (begin_date_required trong ví dụ trên)
```

### Raise với T100 message syntax (7.50+)

```abap
" ✅ RAISE EXCEPTION TYPE ... MESSAGE — shorthand, lấy message từ T100 inline
RAISE EXCEPTION TYPE zcx_travel_validation
  MESSAGE e001(ztr)                    " e=error, 001=msg number, ztr=msg class
  WITH ls_travel-travel_id.            " placeholder &1

" ✅ Wrap sy-msg* sau MESSAGE statement (useful khi convert classic message)
MESSAGE e002(ztr) WITH ls_travel-travel_id INTO DATA(lv_dummy).  " fills sy-msg*
RAISE EXCEPTION TYPE zcx_travel_validation
  EXPORTING
    textid    = VALUE scx_t100key(
      msgid = sy-msgid
      msgno = sy-msgno
      attr1 = 'TRAVEL_ID' )
    travel_id = ls_travel-travel_id.
```

### Đọc exception text

```abap
CATCH zcx_travel_validation INTO DATA(lx_val).
  DATA(lv_text)   = lx_val->get_text( ).          " short text từ T100
  DATA(lv_detail) = lx_val->get_longtext( ).       " long text (nếu có)
  DATA(lv_id)     = lx_val->travel_id.             " custom attribute

  " Log hoặc display
  log_error( lv_text ).
```

## 5. RAISE EXCEPTION — Tất Cả Patterns

```abap
" ✅ Pattern 1 — Basic raise
RAISE EXCEPTION TYPE zcx_not_found.

" ✅ Pattern 2 — Với EXPORTING (pass attributes và textid)
RAISE EXCEPTION TYPE zcx_travel_validation
  EXPORTING
    textid    = zcx_travel_validation=>end_date_before_begin
    travel_id = lv_travel_id.

" ✅ Pattern 3 — MESSAGE shorthand (7.50+)
RAISE EXCEPTION TYPE zcx_travel_validation
  MESSAGE e001(ztr) WITH lv_travel_id.

" ✅ Pattern 4 — Chaining (wrap existing exception)
RAISE EXCEPTION TYPE zcx_business_error
  EXPORTING
    textid   = zcx_business_error=>processing_failed
    previous = lx_previous.            " ← chain previous exception

" ✅ Pattern 5 — Re-raise current exception (trong CATCH)
TRY.
    do_something( ).
  CATCH zcx_technical_error INTO DATA(lx).
    log_error( lx ).
    RAISE EXCEPTION lx.    " ← re-raise same object (không phải TYPE)
ENDTRY.

" ✅ Pattern 6 — RESUMABLE (xem Section 8)
RAISE RESUMABLE EXCEPTION TYPE zcx_resumable_warning
  EXPORTING textid = zcx_resumable_warning=>non_critical_issue.

" ✅ Pattern 7 — THROW trong conditional expression (7.54+)
DATA(result) = COND string(
  WHEN lv_value > 0 THEN lv_value
  ELSE THROW zcx_invalid_parameter( )    " ← raise exception inline
).

" ❌ TUYỆT ĐỐI KHÔNG dùng cx_root trực tiếp
RAISE EXCEPTION TYPE cx_root.   " ← caller không biết catch gì
```

## 6. TRY / CATCH / CLEANUP / ENDTRY

### Cấu trúc đầy đủ

```abap
TRY.
    " Protected code — exceptions từ đây sẽ được handle bởi CATCH blocks bên dưới
    DATA(travel) = travel_repository->get_by_id( lv_travel_id ).
    DATA(price)  = price_calculator->calculate( travel ).

  CATCH zcx_travel_not_found INTO DATA(lx_not_found).
    " Specific handler — catch trước khi parent
    log_warning( |Travel { lv_travel_id } not found: { lx_not_found->get_text( ) }| ).
    RETURN.   " hoặc set default

  CATCH zcx_travel_validation INTO DATA(lx_val).
    " Another specific handler
    RAISE EXCEPTION TYPE zcx_travel_processing_failed
      EXPORTING
        textid   = zcx_travel_processing_failed=>validation_failed
        previous = lx_val.    " chain original exception

  CATCH cx_root INTO DATA(lx_any).
    " Last resort — catch all (chỉ dùng ở top-level boundary!)
    log_fatal( lx_any ).
    RAISE EXCEPTION lx_any.   " re-raise — không nuốt exception

  CLEANUP.
    " Luôn chạy khi có exception KHÔNG được handle trong TRY block này
    " (chạy trước khi exception propagate lên caller)
    " Dùng để: release resources, close file handles, rollback
    IF lo_db_connection IS BOUND.
      lo_db_connection->close( ).
    ENDIF.

ENDTRY.
```

### CATCH nhiều exception types trong 1 CATCH

```abap
" ✅ Catch multiple types — xử lý giống nhau
CATCH zcx_travel_not_found zcx_booking_not_found INTO DATA(lx).
  log_not_found( lx->get_text( ) ).

" ✅ Catch parent class — bắt tất cả subclasses
CATCH zcx_travel_error INTO DATA(lx_travel).   " bắt validation, not_found, conflict, ...
```

### Thứ tự CATCH — specific trước, parent sau

```abap
" ✅ Correct order — specific → general
TRY.
    ...
  CATCH zcx_travel_validation.    " specific child
  CATCH zcx_travel_error.         " parent (catches remaining children)
  CATCH cx_root.                  " last resort
ENDTRY.

" ❌ Wrong order — parent bắt hết, specific không bao giờ reach
TRY.
    ...
  CATCH cx_root.                  " bắt tất cả ngay đây
  CATCH zcx_travel_validation.    " DEAD CODE — không bao giờ reached
ENDTRY.
```

### CLEANUP — phải giữ sạch

```abap
" ✅ CLEANUP chạy khi exception propagate ra ngoài TRY block
" Không chạy khi exception được CATCH bên trong cùng TRY block
TRY.
    lo_file = open_file( lv_path ).
    process_file( lo_file ).
    lo_file->close( ).   " chỉ chạy khi không có exception

  CLEANUP.
    " Đảm bảo file luôn được close dù có exception
    IF lo_file IS BOUND.
      TRY.
          lo_file->close( ).
        CATCH cx_root.   " ignore error trong cleanup
      ENDTRY.
    ENDIF.
ENDTRY.
```

## 7. Exception Chaining — PREVIOUS

Chain exceptions qua nhiều tầng call → giữ nguyên root cause khi wrap.

```abap
" Layer 1: DB layer — raise technical exception
CLASS zcl_db_travel_repository IMPLEMENTATION.
  METHOD get_by_id.
    SELECT SINGLE travel_id, status FROM ztravel
      WHERE travel_id = @travel_id
      INTO @DATA(ls).
    IF sy-subrc <> 0.
      RAISE EXCEPTION TYPE zcx_db_read_error    " technical exception
        EXPORTING
          textid    = zcx_db_read_error=>record_not_found
          travel_id = travel_id.
    ENDIF.
    result = ls.
  ENDMETHOD.
ENDCLASS.

" Layer 2: Service layer — wrap vào business exception, chain previous
CLASS zcl_travel_service IMPLEMENTATION.
  METHOD get_travel.
    TRY.
        result = repository->get_by_id( travel_id ).
      CATCH zcx_db_read_error INTO DATA(lx_db).
        RAISE EXCEPTION TYPE zcx_travel_not_found   " business exception
          EXPORTING
            textid    = zcx_travel_not_found=>travel_does_not_exist
            travel_id = travel_id
            previous  = lx_db.   " ← chain: giữ root cause!
    ENDTRY.
  ENDMETHOD.
ENDCLASS.

" Layer 3: Handler — đọc full exception chain
CLASS zcl_travel_handler IMPLEMENTATION.
  METHOD handle_get_travel.
    TRY.
        result = travel_service->get_travel( lv_id ).
      CATCH zcx_travel_not_found INTO DATA(lx).
        " Đọc chain
        DATA(lv_msg)  = lx->get_text( ).           " business message
        DATA(lo_root) = lx->previous.              " TYPE REF TO cx_root
        IF lo_root IS BOUND.
          DATA(lv_root_msg) = lo_root->get_text( ). " root cause message
        ENDIF.
        log_error( |{ lv_msg } (caused by: { lv_root_msg })| ).
    ENDTRY.
  ENDMETHOD.
ENDCLASS.
```

## 8. Resumable Exceptions

Cho phép caller "sửa" và **tiếp tục** xử lý từ điểm raise — thay vì abort.
Hữu ích cho: validation warnings, batch processing với non-fatal errors.

```abap
" ✅ Raiser: khai báo RESUMABLE trong RAISING clause
CLASS zcl_batch_processor DEFINITION.
  PUBLIC SECTION.
    METHODS process_item
      IMPORTING item          TYPE zs_item
      RAISING   RESUMABLE( zcx_item_warning ).   " ← RESUMABLE trong RAISING
ENDCLASS.

CLASS zcl_batch_processor IMPLEMENTATION.
  METHOD process_item.
    " Validate
    IF item-quantity < 0.
      RAISE RESUMABLE EXCEPTION TYPE zcx_item_warning   " ← RESUMABLE
        EXPORTING textid = zcx_item_warning=>negative_quantity.
      " ← nếu caller gọi RESUME, code tiếp tục từ đây
    ENDIF.

    " Normal processing — chỉ reach đây nếu không raise hoặc caller RESUME
    process_valid_item( item ).
  ENDMETHOD.
ENDCLASS.

" ✅ Caller: CATCH BEFORE UNWIND → quyết định có RESUME không
CLASS zcl_main IMPLEMENTATION.
  METHOD process_all_items.
    DATA lt_warnings TYPE TABLE OF string.

    LOOP AT lt_items INTO DATA(item).
      TRY.
          batch_processor->process_item( item ).

        CATCH BEFORE UNWIND zcx_item_warning INTO DATA(lx_warn).
          " BEFORE UNWIND: context chưa bị delete → có thể RESUME
          APPEND lx_warn->get_text( ) TO lt_warnings.

          IF lx_warn->is_resumable = abap_true.   " check nếu thực sự resumable
            RESUME.   " ← tiếp tục xử lý từ sau RAISE RESUMABLE
          ENDIF.
          " Nếu không RESUME → exception propagate bình thường
      ENDTRY.
    ENDLOOP.

    " Log all warnings
    log_warnings( lt_warnings ).
  ENDMETHOD.
ENDCLASS.
```

> **Lưu ý kỹ thuật:**
> - `RESUMABLE` property không phải của exception class mà là của **RAISE statement**
> - Có thể RAISE RESUMABLE bất kỳ exception class nào
> - `CATCH BEFORE UNWIND` bắt buộc để có thể RESUME (giữ call stack context)
> - Nếu CATCH BEFORE UNWIND mà không gọi RESUME → exception propagate như bình thường
> - `lx->is_resumable = abap_true` chỉ set khi dùng INTO + BEFORE UNWIND

## 9. RAISE SHORTDUMP — ABAP Cloud

Trong ABAP Cloud, `MESSAGE TYPE 'A'` (abort) bị forbidden. Thay bằng `RAISE SHORTDUMP`.

```abap
" ✅ ABAP Cloud — RAISE SHORTDUMP thay MESSAGE TYPE 'A'
" Dùng khi: program state hoàn toàn corrupt, không thể tiếp tục

RAISE SHORTDUMP TYPE zcx_fatal_config_error
  EXPORTING
    textid = zcx_fatal_config_error=>system_config_missing.
" → tạo ST22 dump với exception class info → traceable

" ❌ Classic — forbidden trong ABAP Cloud
MESSAGE 'System configuration missing' TYPE 'A'.   " forbidden in Cloud
RAISE EXCEPTION TYPE cx_root.   " không nên — tooabstract

" ✅ On-Premise — cả 2 cách đều hoạt động
" Nhưng RAISE SHORTDUMP preferred vì stacktrace rõ hơn plain MESSAGE
```

## 10. Exception Handling ở Boundary Layer

### Patterns cho các boundary points

```abap
" Boundary 1: RAP Handler (DO handler)
" → Dùng RAP FAILED / REPORTED tables, không raise exception ra ngoài
METHOD validate.
  LOOP AT keys INTO DATA(key).
    TRY.
        validate_travel( key-travel_id ).
      CATCH zcx_travel_validation INTO DATA(lx).
        APPEND VALUE #( travel_id = key-travel_id ) TO failed-travel.
        APPEND VALUE #(
          travel_id = key-travel_id
          %msg      = new_message_from_class(
            severity  = if_abap_behv_message=>severity-error
            textid    = zcx_travel_validation=>end_date_before_begin
          )
        ) TO reported-travel.
    ENDTRY.
  ENDLOOP.
ENDMETHOD.

" Boundary 2: RFC-enabled function module wrapper
" → Dùng EXCEPTIONS parameter hoặc BAPIRET2 return table
FUNCTION z_travel_get_details.
  *"--- IMPORTING: iv_travel_id
  *"--- EXPORTING: es_travel
  *"--- EXCEPTIONS: not_found others 1
  TRY.
      es_travel = travel_service->get_travel( iv_travel_id ).
    CATCH zcx_travel_not_found.
      RAISE not_found.
    CATCH cx_root INTO DATA(lx).
      MESSAGE lx TYPE 'I' DISPLAY LIKE 'E'.
      RAISE EXCEPTION_TYPE others.
  ENDTRY.
ENDFUNCTION.

" Boundary 3: ADT run (if_oo_adt_classrun)
METHOD if_oo_adt_classrun~main.
  TRY.
      DATA(result) = travel_service->process( ls_input ).
      out->write( result ).
    CATCH cx_root INTO DATA(lx).
      out->write( |Error: { lx->get_text( ) }| ).
      out->write( lx->get_source_position( ) ).
  ENDTRY.
ENDMETHOD.
```

## 11. Anti-Patterns

### EX-AP-01 🔴 — Empty CATCH block (exception swallowing)

```abap
" ❌ WRONG — exception bị nuốt hoàn toàn → silent failure, undefined state
TRY.
    result = get_data( lv_id ).
  CATCH cx_root.
    " nothing                 " ← developer sẽ mất hàng giờ debug tại sao không có data
ENDTRY.

" ✅ CORRECT — ít nhất log, hoặc re-raise, hoặc set fallback rõ ràng
TRY.
    result = get_data( lv_id ).
  CATCH zcx_not_found.
    result = default_value( ).   " explicit fallback — intentional
  CATCH cx_root INTO DATA(lx).
    log_error( lx ).
    RAISE EXCEPTION lx.          " re-raise nếu không thể recover
ENDTRY.
```

---

### EX-AP-02 🔴 — CATCH cx_root ở mọi nơi (Pokemon exception: "gotta catch 'em all")

```abap
" ❌ WRONG — catch all everywhere hides real errors
METHOD process.
  TRY.
      step_a( ).
    CATCH cx_root.   " ← step_a có thể fail vì nhiều lý do — all hidden
  ENDTRY.
  TRY.
      step_b( ).
    CATCH cx_root.   " ← same problem
  ENDTRY.
ENDMETHOD.

" ✅ CORRECT — catch specific, let unexpected propagate
METHOD process.
  TRY.
      step_a( ).
      step_b( ).
    CATCH zcx_validation_error INTO DATA(lx_val).
      handle_validation( lx_val ).
    CATCH zcx_not_found INTO DATA(lx_nf).
      handle_not_found( lx_nf ).
    " cx_root không có ở đây → propagate lên caller
    " (chỉ add cx_root handler tại true boundary)
  ENDTRY.
ENDMETHOD.
```

### EX-AP-03 🟠 — Dùng exception cho control flow thông thường

```abap
" ❌ WRONG — exception cho case bình thường (không phải error)
METHOD get_first_open_travel.
  TRY.
      result = lt_travels[ status = 'O' ].  " raises cx_sy_itab_line_not_found
    CATCH cx_sy_itab_line_not_found.
      result = VALUE #( ).   " empty = no open travel
  ENDTRY.

" ✅ CORRECT — dùng VALUE OPTIONAL cho case bình thường (không phải error)
METHOD get_first_open_travel.
  result = VALUE #( lt_travels[ status = 'O' ] OPTIONAL ).
  " returns initial value nếu không tìm thấy — không cần TRY/CATCH
```

### EX-AP-04 🟠 — RAISE EXCEPTION TYPE cx_root trực tiếp

```abap
" ❌ WRONG — cx_root quá generic, caller không biết catch gì
IF lv_id IS INITIAL.
  RAISE EXCEPTION TYPE cx_root.
ENDIF.

" ✅ CORRECT — dùng specific exception class
IF lv_id IS INITIAL.
  RAISE EXCEPTION TYPE zcx_invalid_parameter
    EXPORTING textid = zcx_invalid_parameter=>travel_id_empty.
ENDIF.
```

### EX-AP-05 🟠 — Không chain exception khi wrap (mất root cause)

```abap
" ❌ WRONG — root cause bị mất khi wrap
TRY.
    lo_db->read( lv_id ).
  CATCH zcx_db_error INTO DATA(lx_db).
    RAISE EXCEPTION TYPE zcx_business_error.   " ← lx_db bị mất!
ENDTRY.

" ✅ CORRECT — chain với PREVIOUS
TRY.
    lo_db->read( lv_id ).
  CATCH zcx_db_error INTO DATA(lx_db).
    RAISE EXCEPTION TYPE zcx_business_error
      EXPORTING previous = lx_db.    " ← root cause preserved
ENDTRY.
```

### EX-AP-06 🟡 — CATCH với wrong order (parent trước specific)

```abap
" ❌ WRONG — zcx_validation unreachable vì cx_root bắt hết trước
TRY.
    validate_travel( ls_travel ).
  CATCH cx_root INTO DATA(lx).         " bắt TẤT CẢ
    log_error( lx ).
  CATCH zcx_travel_validation.         " DEAD CODE — không bao giờ reach
    " specific handling...
ENDTRY.

" ✅ CORRECT — specific trước, general sau
TRY.
    validate_travel( ls_travel ).
  CATCH zcx_travel_validation INTO DATA(lx_val).   " specific trước
    handle_validation( lx_val ).
  CATCH cx_root INTO DATA(lx_any).                 " general sau
    log_unexpected( lx_any ).
    RAISE EXCEPTION lx_any.
ENDTRY.
```

### EX-AP-07 🟡 — Exception class tên sai prefix hoặc quá generic

```abap
" ❌ WRONG — không theo naming convention
CLASS zcl_error DEFINITION ...        " ← prefix ZCL_, không phải ZCX_
CLASS zcx_error DEFINITION ...        " ← quá generic, không nói lên gì
CLASS zcx_my_exception DEFINITION ... " ← 'my' không có nghĩa

" ✅ CORRECT — ZCX_ prefix, tên mô tả domain + loại lỗi
CLASS zcx_travel_validation   DEFINITION ... " domain: travel, type: validation
CLASS zcx_booking_not_found   DEFINITION ... " domain: booking, type: not_found
CLASS zcx_payment_timeout     DEFINITION ... " domain: payment, type: timeout
CLASS zcx_config_missing      DEFINITION ... " domain: config, type: missing
```
